# 壁毯修复定位网校核

浏览器中建立 2–4 行 × 2–4 列矩形单元的定位网，拖动或录入织补后各网结的整数坐标，
录入 3–12 个原网纹样标记；点击“校核”后，应用把每个单元视为**连续双线性形变**，
将标记换算到织补坐标，并对整张网做**连续不翻折判定**（不以有限采样点替代）。

校核通过后，可录入 2–8 个织补面上的整数**复核针位**并发起**反向追溯**：
应用对每个单元的双线性形变**解析求逆**，枚举并验证闭合单元域内的全部根，
确认针位实际对应原网中的哪一处纹样坐标。只有全部针位各自对应唯一原网位置时，
才输出原网坐标、所在单元与局部参数，修复师不会依据歧义针位落针。

## 连续判定的数学依据

单元的织补映射为双线性插值 `P(s,t)`，其雅可比行列式 `J(s,t)` 关于 `(s,t)` 是双线性函数。
双线性函数在矩形域上的最小值必在某一角点取得（固定 t 时关于 s 线性，两端关于 t 亦线性），因此：

```
J(s,t) > 0  ∀(s,t)∈[0,1]²   ⇔   四个角点的 J 值均 > 0
```

检查 4 个角点即等价于检查单元内**任意内部位置**，这是严格的连续判定而非采样。
角点 J 值即该角点两条邻边向量的叉积；网结坐标为整数时 J 必为整数，故 `J > 0 ⇔ J ≥ 1`，无数值模糊地带。

- **翻折**：某角点 `J < 0`；**退化**：某角点 `J = 0`。
- 首项失败证据按**行优先单元顺序**与**固定角点顺序**（C0 左上 → C1 右上 → C2 右下 → C3 左下）报告。
- 相邻单元共享边：共享边两侧的双线性映射在边上退化为同一对端点的同一线性插值，
  结构化网格天然共用网结，并由 `checkSharedEdges` 显式核验。
- 只有全网通过时才输出纹样标记的换算位置，避免把失真坐标交给织补师。
- 网结拖动或任何字段修改都会立即使旧结论失效（页面提示重新校核）。

## 反向追溯的数学依据

把单元映射写成仿射分解 `P(s,t) = A + B·s + D·t + E·s·t`
（`A = C0`，`B = C1-C0`，`D = C3-C0`，`E = C0-C1+C2-C3`）。给定针位 `Q`，令 `d = Q - A`，
消去 `s` 后得到关于 `t` 的二次方程（系数全部为整数叉积，可精确计算）：

```
a·t² + b·t + c = 0,   a = E×D,  b = B×D + d×E,  c = d×B
```

- 对每个单元用**数值稳定的求根公式**枚举全部实根（`a = 0` 时退化为线性方程），
  逐根回代求 `s`（取绝对值较大的分母；已校核网格 `J > 0` 保证闭合域内分母非零），
  只保留落在**闭合单元域** `[0,1]²` 内的根，并把每个候选根**正向代入 `P(s,t)` 验证**
  确实映回针位。这是解析枚举与验证，**不依赖网格采样或迭代初值**。
- 已校核网格保证每个单元在闭合域内是单射（同一单元至多一个域内根）；
  但 `J > 0` 是局部性质，**不排除非相邻单元的像相互重叠**，因此必须全网枚举：
  - 相邻单元公共边/公共角点上的**同一原网位置**被多个单元给出时**合并为一项**，
    展示单元与局部参数按既有 `locateCell` 归属规则确定（内部公共边归入局部坐标为 0
    的单元、外边界归入末单元、角点恒归 C0），与纹样标记正向换算的归属完全一致，显示稳定；
  - 非相邻单元给出**不同**原网位置（重叠歧义）、针位落在网外（全部单元在闭合域内
    均无有效根，含二次方程无实根的情形）→ 该针位不可追溯；
  - 按针位录入顺序返回**首个不可追溯证据**，其余针位的追溯结果一律不输出；
    只有全部针位各自唯一时才展示原网坐标、所在单元与局部参数。
- 反向追溯以**既有定位网已校核通过**为前提：服务端与页面都会先重做几何校核，
  未通过则拒绝追溯。
- 任何网结、原网纹样或复核针位编辑都立即使追溯结论失效；
  未录入复核针位的历史草稿继续保持原有校核与结果（`/api/verify` 行为不变）。

## 运行（Docker Compose）

```bash
# 启动 Web 服务（宿主机端口可配置，默认 8080）
WEB_PORT=9000 docker compose up --build web
# 打开 http://localhost:9000

# 一次性验收：代码测试 → 构建 → 健康与校核/追溯样例冒烟，以退出码报告结论
docker compose up --build --exit-code-from verify
echo $?   # 0 = 验收通过
```

- Web 服务健康检查：`GET /healthz`（Compose healthcheck 与 Dockerfile HEALTHCHECK 均使用）。
- 校核 API：`POST /api/verify`，请求体 `{rows, cols, knots, markers}`，
  与浏览器页面共用同一数学模块 `src/shared/bilinear.js`。
- 反向追溯 API：`POST /api/trace`，请求体 `{rows, cols, knots, needles}`（2–8 个整数针位），
  与浏览器页面共用同一数学模块 `src/shared/trace.js`；
  返回 `{ok, stage, traces}` 或首个不可追溯证据 `firstFailure`（此时 `traces` 为 `null`）。

## 本地开发（Node ≥ 20，无第三方依赖）

```bash
npm test          # 单元测试（node:test）
npm run build     # 构建 dist/（含恒等网格校核与反向追溯自检）
npm start         # 构建并启动服务（PORT 环境变量可改端口，默认 8080）
npm run smoke     # 对运行中的服务做健康 + 校核/追溯样例冒烟
```

## 目录结构

```
src/shared/bilinear.js   # 核心数学：双线性映射、连续不翻折判定、标记换算（浏览器/服务端/测试共用）
src/shared/trace.js      # 反向追溯：双线性形变解析求逆、闭合域根枚举与验证、位置合并（同源共用）
src/server.js            # 静态服务 + /healthz + /api/verify + /api/trace
src/public/              # 浏览器页面（画布拖动、字段录入、校核与追溯结论展示）
scripts/build.js         # 构建：自检 + 组装 dist/ + SHA-256 清单
scripts/smoke.js         # 冒烟：健康检查 + 校核样例 + 唯一追溯/公共边/重叠歧义/网外/拒追样例
test/                    # node:test 单元测试
Dockerfile               # 单镜像：构建期自检，运行时非 root
docker-compose.yml       # web（健康检查、端口可配）+ verify（一次性验收，退出码报告）
```
