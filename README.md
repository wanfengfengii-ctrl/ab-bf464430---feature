# 壁毯修复定位网校核与反向追溯

浏览器中建立 2–4 行 × 2–4 列矩形单元的定位网，拖动或录入织补后各网结的整数坐标，
录入 3–12 个原网纹样标记；点击“校核”后，应用把每个单元视为**连续双线性形变**，
将标记换算到织补坐标，并对整张网做**连续不翻折判定**（不以有限采样点替代）。

定位网校核通过后，修复师可录入 **2–8 个织补面上的整数复核针位**并发起**反向追溯**，
确认每个针位实际对应原网中的哪一处纹样坐标：应用对每个单元的双线性形变做
**闭式解析求逆**，在闭合单元域内**枚举并验证全部根**（不采样、不设迭代初值），
只有全部针位各自唯一对应原网位置时才输出结果。

## 连续判定的数学依据

单元的织补映射为双线性插值 `P(s,t)`，其雅可比行列式 `J(s,t)` 关于 `(s,t)` 是双线性函数。
双线性函数在矩形域上的最小值必在某一角点取得（固定 t 时关于 s 线性，两端关于 t 亦线性），因此：

```
J(s,t) > 0  ∀(s,t)∈[0,1]²   ⇔   四个角点的 J 值均 > 0
```

检查 4 个角点即等价于检查单元内**任意内部位置**，这是严格的连续判定而非采样。
角点 J 值即该角点两条邻边向量的叉积；网结坐标为整数时 J 必为整数，故 `J > 0 ⇔ J ≥ 1`，无数值模糊地带。

- **翻折**：某角点 `J < 0`；**退化**：某角点 `J = 0`。
- 首项失败证据按**行优先单元顺序**与**固定角点顺序**（C0 左上 → C1 右上 → C2 右下 → C3 左下）报告。
- 相邻单元共享边：共享边两侧的双线性映射在边上退化为同一对端点的同一线性插值，
  结构化网格天然共用网结，并由 `checkSharedEdges` 显式核验。
- 只有全网通过时才输出纹样标记的换算位置，避免把失真坐标交给织补师。
- 网结拖动或任何字段修改都会立即使旧结论失效（页面提示重新校核）。

## 反向追溯的精确求逆数学依据

校核通过后，给定织补面上的**整数**针位 q，要在每个闭合单元 [0,1]² 内解双线性方程

```
P(s,t) = c0 + a·s + b·t + d·s·t = q,   a=c1−c0, b=c3−c0, d=c0−c1−c3+c2
```

应用**不做网格采样、不设迭代初值**，而是闭式消元：由一个分量把 s 表为 t 的分式
（`s=(e−bt)/(a+dt)`，e=q−c0），代入另一分量得到 t 的**整系数二次方程**
`A t² + B t + C = 0`。其根形如 `(P + Q·√D)/den`，属于二次数域 **Q(√D)**；
s 经分母有理化后仍是同一数域中的元素。于是：

- **枚举全部根**：二次方程至多两个实根，逐个构造，无一遗漏；
- **闭合域判定**：`0 ≤ s,t ≤ 1` 通过 BigInt 精确符号判定完成
  （异号时平方化归为整数比较 `P²` 与 `Q²D`；完全平方判别式先退化为有理数，避免范数为零的陷阱）；
- **精确验证**：把候选根代回 x、y 两个分量方程，展开后的有理部与 √D 部必须**同时精确为 0**，
  全程 BigInt，无容差；浮点仅用于生成展示用十进制近似。

消元恢复分母在某根处为 0 时（该分量只约束 t），精确改沿另一分量消元并按数域相等去重，
仍保证全部根被枚举。校核通过（四角 J>0）的单元是局部微分同胚，闭合像内至多一个原像；
跨单元则可能有多个命中。

**唯一性裁决与公共边合并（按针位录入顺序，首个失败即止）**

- 把每个命中折算为全局原网坐标 `(u,v)=(c+s, r+t)`，按 **BigInt 数域精确相等**聚类：
  相邻单元公共边、乃至四个单元共有的内部顶点上的同一位置合并为一项；
- 合并项按既有 `locateCell` 的**固定边界约定**稳定归属（内部整数坐标归 s=0/t=0 一侧，
  右/下外边界归 s=1/t=1 末单元），结果可复现；
- 只有**全部针位**都唯一时才输出原网坐标、所在单元与局部参数（附 BigInt 精确证据）；
- 出现以下任一情况，按针位录入顺序返回**首个不可追溯证据**且不输出其余追溯结果：
  - 非相邻单元给出**不同**原网位置（重叠歧义，样例 G）；
  - 针位不在任何单元闭合像内 / 方程无有效根（落在网外）；
  - 单元退化导致方程多根（防御性，前置的不翻折校核已拦截 J≤0）。

任何**网结、原网纹样标记或复核针位**的编辑都会使追溯结论失效；其中针位编辑只影响追溯，
不触碰与针位无关的既有校核结果——未录入复核针位的历史草稿继续保持原有校核与换算结果。

### 内置重叠歧义样例（非采样才能严格识别）

`scripts/smoke.js` 样例 G 使用一个 2 行 × 4 列的**开口螺旋**整数定位网：8 个单元四角
雅可比全部为正（J<sub>min</sub>=1839，校核通过），但首片与末片的像发生面积重叠，
整数针位 `(173,132)` 同时是单元 `(1,0)` 内点 `(u,v)≈(0.326,1.985)` 与非相邻单元
`(1,3)` 内点 `(u,v)≈(3.815,1.806)` 的像。该针位被精确判为歧义并拦截，
而同一网上的网结顶点与公共边整数中点仍可唯一追溯（公共边命中被合并）。

## 运行（Docker Compose）

```bash
# 启动 Web 服务（宿主机端口可配置，默认 8080）
WEB_PORT=9000 docker compose up --build web
# 打开 http://localhost:9000

# 一次性验收：代码测试 → 构建 → 健康与校核样例冒烟，以退出码报告结论
docker compose up --build --exit-code-from verify
echo $?   # 0 = 验收通过
```

- Web 服务健康检查：`GET /healthz`（Compose healthcheck 与 Dockerfile HEALTHCHECK 均使用）。
- 校核 API：`POST /api/verify`，请求体 `{rows, cols, knots, markers}`，
  与浏览器页面共用同一数学模块 `src/shared/bilinear.js`。

## 本地开发（Node ≥ 20，无第三方依赖）

```bash
npm test          # 单元测试（node:test）
npm run build     # 构建 dist/（含恒等网格自检）
npm start         # 构建并启动服务（PORT 环境变量可改端口，默认 8080）
npm run smoke     # 对运行中的服务做健康 + 校核样例冒烟
```

## 目录结构

```
src/shared/bilinear.js   # 核心数学：双线性映射、连续不翻折判定、标记换算（浏览器/服务端/测试共用）
src/server.js            # 静态服务 + /healthz + /api/verify
src/public/              # 浏览器页面（画布拖动、字段录入、结论展示）
scripts/build.js         # 构建：自检 + 组装 dist/ + SHA-256 清单
scripts/smoke.js         # 冒烟：健康检查 + 恒等/翻折/退化/无效坐标样例
test/                    # node:test 单元测试
Dockerfile               # 单镜像：构建期自检，运行时非 root
docker-compose.yml       # web（健康检查、端口可配）+ verify（一次性验收，退出码报告）
```
